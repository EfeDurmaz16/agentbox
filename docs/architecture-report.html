Positioning — OpenAI Agents SDK vs Agentbox

Why Both Exist

OpenAI's April 2026 Agents SDK update added sandboxing, guardrails, and a long-horizon harness. Their approach: safety inside the SDK. Agents must be built with their SDK to get protection.

Agentbox is the opposite: safety outside the agent. Any agent — OpenClaw, Hermes, Claude Code, Codex, custom scripts — gets intercepted at the OS level. No SDK integration needed.

Key insight: OpenAI protects agents they control. Agentbox protects the machine from agents it does not control. These are complementary — an OpenAI SDK agent with built-in guardrails, running on a machine with Agentbox, gets both layers.

IPC Protocol (Shim to Daemon)

Shim sends (Unix socket, newline-delimited JSON)
{
  "binary": "git",
  "args": ["push", "origin", "main"],
  "cwd": "/Users/efe/agentbox",
  "parent_process": "claude-code",
  "pid": 12345
}

Daemon responds
{
  "bucket": "approve",
  "decision": "approved",
  "reason": "git push to remote",
  "real_binary": "/usr/bin/git"
}

Why OS-Level, Not SDK-Level

OpenAI, Anthropic, and others are building safety into their agent SDKs. This solves safety for agents built with those SDKs. But:

The real world has many agents. A developer runs OpenClaw (open-source, no SDK), Claude Code (Anthropic), Codex CLI (OpenAI), and custom bash scripts — all on the same machine, all day. No single SDK covers all of them. Agentbox sits below all of them, at the OS boundary, and catches every dangerous command regardless of origin.

This is the Tailscale insight: do not fix every app's networking — fix it once at the OS layer. Do not fix every agent's safety — fix it once where commands actually execute.
