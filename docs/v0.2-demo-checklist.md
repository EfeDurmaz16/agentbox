# Agentbox v0.2 Demo Checklist

This checklist defines the honest public demo path for the current Agentbox
product. It is a release/demo operator artifact, not a claim that every
provider is complete.

## Support Levels To Say Out Loud

- `direct-host`: shipped local governance path.
- `podman`: experimental compatibility backend when Podman is installed.
- `agentpod-linux`: prototype native primitives behind `AGENTBOX_LINUX_NATIVE=1`.
- `agentpod-macos` and `agentpod-windows`: descriptor/plan compiler only.
- `remote-agentpod`: experimental attached-worker contract; worker-side
  sandboxing is not complete.

## Pre-Demo Gate

Run:

```sh
cargo build --release
AGENTBOX_RELEASE_ALLOW_DOCTOR_FAILURE=1 scripts/release-readiness.sh
scripts/demo-v0.2.sh
```

Required demo artifacts:

- `target/agentbox-release-readiness/manifest.json`
- `target/agentbox-release-readiness/doctor.json`
- `target/agentbox-release-readiness/providers.json`
- `target/agentbox-release-readiness/setup-plan.json`
- `target/agentbox-release-readiness/signing.json`

`signing.json` must say `signed: false` unless real release signing has been
configured and verified.

## Demo Flow

1. Show the product contract.

   ```sh
   scripts/demo-v0.2.sh
   agentbox providers
   agentbox providers --json
   ```

2. Show non-mutating setup guidance.

   ```sh
   agentbox setup --dry-run --wizard
   agentbox setup-plan
   agentbox doctor --json
   ```

3. Show an AgentPod plan without execution.

   ```sh
   agentbox run --plan --risk high --workspace-mode overlay-review --json -- echo demo
   agentbox native-plan --provider agentpod-macos -- echo demo
   ```

4. Show manifest generation for a general agent.

   ```sh
   agentbox minipod-spec hermes \
     --workspace . \
     --agent-profile research \
     --network-mode first-contact \
     --allow-domain api.openai.com \
     --workspace-mode overlay-review
   ```

5. Show review and session UX.

   ```sh
   agentbox sessions --json
   agentbox sessions --watch
   agentbox review <session-id> --json
   agentbox review <session-id> --tui
   ```

6. Show evidence export when a session/audit store exists.

   ```sh
   agentbox evidence --limit 20
   agentbox evidence --verify
   ```

7. Optional remote attached-worker proof.

   ```sh
   scripts/smoke-remote-worker.sh
   ```

8. Optional Podman compatibility proof when Podman exists.

   ```sh
   scripts/smoke-podman-bridge.sh
   ```

   If Podman is absent, the script must skip honestly instead of passing a fake
   provider proof.

## Claims To Avoid

- Do not claim bypass-proof host isolation.
- Do not claim native macOS or Windows execution.
- Do not claim Podman is Agentbox-native isolation.
- Do not claim release artifacts are signed while `signing.json` says
  `signed: false`.
- Do not claim FIDES, AGIT, or OAPS live integration without external adapters.

## Demo Success Bar

- Setup guidance is understandable without editing shell files automatically.
- Provider status is visibly separated into shipped, experimental, prototype,
  descriptor-only, and unavailable states.
- A high-risk AgentPod plan recommends stronger isolation without claiming that
  descriptor-only providers are runnable.
- Review, sessions, and evidence commands are visible as operator workflows.
- Optional live-provider demos either pass with real prerequisites or skip with
  a clear reason.
